# ReceiptVault

가죽공방 경비·영수증 관리 앱. 영수증을 찍어 두면 연말에 **Schedule C 줄번호별 합계**가
바로 나온다.

- **React + Supabase + Cloudflare Worker**, 빌드 단계 없음
- 태블릿 브라우저만으로 설치·수정·배포가 가능하도록 만들어져 있다

---

## 왜 빌드 도구가 없나

Vite 같은 빌드 단계를 넣으면 코드를 한 줄 고칠 때마다 `npm run build`를 돌릴 PC가 필요해진다.
이 앱은 PC 없이 굴려야 해서, 브라우저가 React와 Babel을 직접 받아 쓰는 방식으로 짰다.
**파일 하나 고치고 새로고침하면 그게 배포다.**

대신 첫 로딩이 1초쯤 느리다. 개인용 앱에서는 문제되지 않는 값이다.

---

## 파일 구조

```
index.html              화면 뼈대 + 스타일 전부
manifest.webmanifest    홈 화면 설치용
sw.js                   서비스워커 (network-first)
icon.svg                앱 아이콘
config.js               ★ 여기만 채우면 됨 (Supabase 주소/키)
categories.js           Schedule C 분류표
core.js                 유틸 + Supabase 접근 + AI 호출
app.jsx                 화면 전부
schema.sql              DB 설정 SQL (한 번만 실행)
worker.js               영수증 자동 인식 프록시 (나중 단계)
README.md  HANDOFF.md   문서
```

**폴더가 없는 이유**: 안드로이드 파일 선택기는 폴더를 통째로 고르지 못한다.
파일을 전부 한 층에 두어야 태블릿에서 GitHub에 12개를 한 번에 올릴 수 있다.
PC가 생기더라도 이 구조를 굳이 바꿀 이유는 없다 — 파일이 열 몇 개뿐이다.

의존성은 `index.html`의 script 순서가 전부다. 새 파일을 넣으면 **자기가 쓰는 것보다 뒤에**
script 태그를 넣어야 한다.

## 설치 순서 (태블릿에서)

### 1단계 — GitHub 저장소

1. `github.com/new` → 이름 `receiptvault` → **Public** → Create
2. 받은 zip을 태블릿 **내 파일** 앱에서 압축 해제
3. 저장소 화면 → `Add file` → `Upload files` → 푼 폴더 안의 **파일 12개를 전부 선택** → Commit
   - 전부 같은 층에 있으므로 한 번에 선택된다.
   - 업로드가 실패하면 `Add file` → `Create new file`로 하나씩 만들어 붙여넣어도 된다.
4. `Settings` → `Pages` → Source: **Deploy from a branch** → `main` / `/ (root)` → Save
5. 1~2분 뒤 `https://jennyryu3d.github.io/receiptvault/` 가 열린다

> **Public이어도 괜찮은 이유**: 코드에 들어가는 Supabase anon key는 원래 공개용 키다.
> 실제 방어는 RLS(본인 데이터만 조회 가능)가 하고, 진짜 비밀인 Anthropic 키는
> Cloudflare Worker 안에만 있다. 영수증 사진과 데이터는 저장소가 아니라 Supabase에 있다.

### 2단계 — Supabase

1. `supabase.com/dashboard` → **New project** (이름 `receiptvault`, 리전 West US)
   - 무료 플랜은 활성 프로젝트 2개까지다. LinkVault가 하나 쓰고 있으니 이게 두 번째다.
2. 왼쪽 **SQL Editor** → `schema.sql` 내용을 통째로 붙여넣고 **Run**
   - 테이블, 보안 규칙, 사진 저장소가 한 번에 만들어진다. 여러 번 돌려도 안전하다.
3. **Project Settings → Data API** 에서 두 값을 복사
   - `Project URL`
   - `anon` / `publishable` key
4. **Authentication → URL Configuration**
   - Site URL: `https://jennyryu3d.github.io/receiptvault/`
   - Redirect URLs 에 같은 주소 추가
   - ★ 이걸 빠뜨리면 로그인 메일의 링크를 눌러도 안 들어와진다. 가장 흔한 함정이다.
5. GitHub에서 `config.js`를 연필 아이콘으로 열어 3, 4단계 값을 채우고 Commit

### 3단계 — 써보기

1. `https://jennyryu3d.github.io/receiptvault/` 접속
2. 이메일 입력 → 받은 링크를 **같은 브라우저**에서 열기
3. `+ 추가` → 사진 찍고 항목 채우고 저장

> 로그인 메일은 Supabase 기본 메일 서버를 쓰는데 **시간당 2통** 제한이 있다.
> 테스트한다고 연달아 누르지 말 것. 한 번 로그인하면 세션이 유지된다.

### 4단계 — 자동 인식 (Anthropic 키가 준비된 뒤)

1. Cloudflare → Workers → Create → 이름 `receiptvault-proxy`
2. 코드 자리에 `worker.js` 내용을 붙여넣고 Deploy
3. Settings → Variables and Secrets → **Secret** 으로 `ANTHROPIC_API_KEY` 추가
   - 반드시 Secret(암호화) 타입. Plaintext로 넣으면 안 된다.
4. `config.js` 의 `AI_PROXY_URL` 에
   `https://receiptvault-proxy.<계정>.workers.dev/extract` 를 넣고 Commit
   - Worker는 경로를 따지지 않으므로 `/extract` 를 빼도 동작한다. 붙여두면
     나중에 이 주소가 무엇인지 알아보기 쉬워서 붙이는 쪽을 권한다.
5. 앱에서 사진을 고르면 가맹점·날짜·금액·분류가 자동으로 채워진다

Worker 안에서 모델과 max_tokens를 고정해 뒀기 때문에 앱 쪽에서 비싼 요청을 만들 수 없다.
배포 주소나 도메인을 바꾸면 `worker.js` 의 `ALLOWED_ORIGINS` 도 같이 고쳐야 한다.
안 그러면 브라우저가 403을 받는다.

## 분류 체계

`categories.js` 하나가 분류의 유일한 출처다. 각 항목에 Schedule C 줄번호가 박혀 있어서,
리포트 화면의 합계를 신고서에 그대로 옮겨 적을 수 있다.

- **매출원가 (Part III)** — 36번 가죽·원자재, 38번 부자재·제작 소모품
- **경비 (Part II)** — 22 공구, 13 장비, 20b 임대료, 25 공과금, 8 광고, 18 사무,
  10 판매수수료, 21 수리, 15 보험, 23 세금·라이선스, 17 전문가 비용,
  24a 출장, 24b 식비(50%), 9 차량, 27a 배송·교육·기타

세 가지는 자동으로 처리된다.

- **식비 50% 규칙** — 100달러를 넣으면 공제 반영액은 50달러로 계산된다
- **사업 사용 비율** — 차량처럼 개인 겸용인 지출은 비율을 낮춰 넣으면 그만큼만 잡힌다
- **분류 나누기** — 아래 참고

리포트의 금액은 이것들이 반영된 **공제 반영액**이고, 실제 지출액이 다르면 아래에 함께 뜬다.

## 분류 나누기 (분할)

가죽과 공구를 한 번에 산 영수증처럼 한 장이 여러 분류에 걸칠 때 쓴다.
입력 화면에서 **⑂ 분류 나누기**를 누르면 줄을 여러 개로 쪼갤 수 있다.

- 쪼갠 금액의 합이 **총액과 맞아야 저장된다.** 남거나 넘치면 얼마인지 위에 표시되고,
  **나머지 넣기** 버튼으로 한 번에 채울 수 있다.
- 줄을 하나만 남기고 지우면 분할이 자동으로 풀린다.
- 목록에서는 대표 분류(금액이 가장 큰 줄) 옆에 `⑂2` 같은 표시가 붙는다.
- 리포트와 CSV는 줄 단위로 집계된다. CSV는 한 영수증이 여러 행으로 나오고,
  `receipt_total` 열이 같은 값으로 반복돼서 어떤 행들이 한 장에서 나왔는지 알 수 있다.
- 사업 사용 비율은 영수증 전체에 걸린다(줄마다 따로 주지 않는다). 한 영수증 안에
  사업용과 개인용이 섞여 있으면, 그건 분할이 아니라 두 건으로 나눠 넣는 게 맞다.
- AI 인식도 분할을 제안할 수 있다. 다만 **분류 key가 실제로 있고 합계가 총액과 정확히
  맞을 때만** 받아들이고, 아니면 조용히 무시하고 단일 분류로 채운다.

## 같이 쓰기

영수증은 **장부(ledger)** 에 담기고, 장부 하나를 여러 사람이 같이 본다.
부부가 각자 자기 이메일로 로그인하면서 같은 장부를 보는 구조다.

- 처음 로그인한 사람이 장부를 하나 만들고 **주인(owner)** 이 된다.
- 주인이 설정에서 상대 이메일을 넣어 초대해 두면, 그 주소로 **앱에 로그인하는 순간
  자동으로 합류**된다. 앱이 초대 메일을 보내지는 않으니 앱 주소는 직접 알려줘야 한다.
- 권한은 둘. **입력 가능(editor)** 은 영수증을 넣고 고칠 수 있고,
  **보기만(viewer)** 은 확인만 한다.
- 영수증마다 **누가 넣었는지**가 기록되고, 식구가 둘 이상이면 상세 화면과 CSV에 나온다.
- 사진 저장 경로가 `{장부id}/{영수증id}.jpg` 라서, 경로 자체가 곧 권한이다.
  장부 식구가 아니면 사진은 존재하지 않는 파일이 된다.

## 통화 — 영수증 그대로 + 달러 환산

영수증에 찍힌 금액과 미국 신고에 쓸 달러 금액을 **둘 다** 저장한다.

- `amount_original` + `currency` — 영수증 그대로 (예: 36,100 KRW)
- `total` — 달러 환산액. 리포트·세무사 자료는 전부 이 값으로 계산한다
- `fx_rate` / `fx_rate_date` / `fx_source` — 어떤 환율을 왜 썼는지

환율은 거래일 기준으로 **유럽중앙은행 공시 환율**을 자동으로 받아온다
(api.frankfurter.dev, 무료·키 불필요). 주말이면 직전 영업일 환율이 온다.

**카드 명세서의 달러 금액을 넣으면 그게 이긴다.** 카드사 환율에는 수수료가 섞여 있어
공시 환율과 조금 다른데, 세무사가 명세서와 대조할 때는 실제 청구액이 맞다.
직접 넣으면 `fx_source`가 `manual`로 바뀌고 문서에도 그렇게 표시된다.

국세청은 "지불하거나 발생한 시점의 환율"을 쓰라고만 하고 특정 출처를 지정하지 않는다.
그래서 **어떤 환율을 썼는지 기록에 남기는 것**이 중요하고, 세무사 자료에 그 표를 따로 넣었다.

분할 금액은 **영수증 통화 기준**으로 넣는다. 영수증을 보고 옮겨 적는 거니까 그게 자연스럽다.
달러 환산은 앱이 한다.

## 같이 쓰기 — 가족·지인·모임

장부 단위로 완전히 격리된다. 한 사람이 여러 장부에 속할 수 있고,
**자기가 속한 장부의 영수증만** 보인다. 사진도 경로가 곧 권한이라 마찬가지다.

교회 모임처럼 여러 명이 동시에 가입하면 **로그인 메일이 병목**이 된다.
Supabase 기본 메일 서버는 프로젝트 전체에서 시간당 2~4통이 한계다.
아래 절차로 메일 서버를 바꾸면 하루 3,000통까지 열린다.

### 메일 서버 붙이기 (Resend, 무료)

1. [resend.com](https://resend.com) 가입 → `API Keys` → `Create API Key` → 값 복사
2. 보낼 주소 정하기
   - 도메인이 있으면 (`jennyryu3d.com`) → `Domains` → 추가 → 안내대로 DNS 세 줄 등록
   - 없으면 Resend가 주는 `onboarding@resend.dev` 로 먼저 시작해도 된다
3. Supabase → `Project Settings` → `Authentication` → `SMTP Settings` → `Enable Custom SMTP`
   - Host: `smtp.resend.com`
   - Port: `587`
   - Username: `resend`
   - Password: 1번의 API Key
   - Sender email / name: 위에서 정한 주소, `ReceiptVault`
4. 같은 화면의 `Rate limit` 을 시간당 100 정도로 올린다

이걸 해두면 여러 명이 한꺼번에 가입해도 안 막힌다.

> **알아둘 것**: 다른 사람의 영수증 자료를 대신 보관하게 된다는 뜻이기도 하다.
> 팔지 않고 아는 사람들끼리 쓰는 정도면 부담이 크지 않지만, 모임이 커지면
> 각자 자기 Supabase를 쓰게 하는 편이 서로 편하다.

## AI 사용량 제한

영수증 인식은 돈이 드는 유일한 부분이라 네 겹으로 막아 뒀다.

1. **로그인 확인** — Worker가 Supabase 토큰을 요구한다. 주소만 알아낸 사람은 못 쓴다
   (Origin 헤더는 프로그램으로 흉내낼 수 있어서 문지기가 될 수 없다)
2. **사용량 한도** — 1인 하루 50장, 전체 하루 300장. `rv_ai_use` 함수가 세면서 막는다
3. **모델·토큰 고정** — 클라이언트가 비싼 모델을 고를 수 없다
4. **이미지 크기 상한** — 토큰 폭탄 방지

한도에 걸려도 **항목을 직접 채워 저장하는 건 그대로 된다.** 인식만 쉰다.

**한도 바꾸기**: Supabase SQL Editor 에서 `rv_ai_use` 함수의 `PER_USER`, `GLOBAL`
두 숫자만 고쳐 다시 Run 하면 끝. 앱도 Worker도 건드릴 필요 없다.

## 세무사에게 보내기

"정리" 탭 오른쪽 위의 **세무사 자료** 버튼.

- **PDF** — 브라우저 인쇄로 만든다. 인쇄 화면에서 대상을 "PDF로 저장"으로 바꾸면
  파일이 떨어진다. 별도 라이브러리를 쓰지 않으므로 앱이 무거워지지 않는다.
  내용은 Schedule C **줄번호 순서**로 정리된 Part III(매출원가) / Part II(경비) 표와
  합계, 그리고 주석(식비 50% 적용, 사업 사용 비율 적용, 영수증 사진 보관 현황).
- **CSV** — 거래 한 줄씩. **열 이름도 분류명도 전부 영문**이다. 세무사가 한글을
  못 읽으니 화면과 달리 여기서는 영문만 쓴다. 분할된 영수증은 줄마다 한 행이 되고
  `receipt_total` 이 반복돼서 한 장에서 나온 행들을 알아볼 수 있다.
- 머리말에 찍히는 사업체명·납세자명은 **설정 → 장부** 에서 넣는다.
- **외화 구입 표** — 거래일, 상호, 통화, 현지 금액, 적용 환율, 달러 금액, 환율 출처.
  외화 건이 하나라도 있으면 자동으로 붙는다.
- **점검 목록** — 보내기 전 화면에서 "사업 목적이 빈 영수증 N건" 같은 걸 세어 보여준다.

### 국세청이 요구하는 기록

지출 하나당 네 가지다: **날짜 · 금액 · 상호 · 사업 목적**.
앞의 셋은 저장할 때 강제되지만 사업 목적은 사람이 적어야 해서, 비어 있으면
상세 화면과 세무사 자료 양쪽에서 경고한다. 식비는 여기에 **누구와 무슨 논의를 했는지**까지
적어야 해서 분류를 식비로 고르면 안내가 뜬다.

문서에 **일부러 "여기엔 없다"고 적어 두는 것들**도 있다. 세무사가 없는 걸 있는 줄 알면
그게 제일 위험하다.

- 차량비는 영수증만 있고 **주행 기록부가 없다** — 그것만으로는 공제가 약하다
- 장비 구입은 **감가상각/Section 179 판단이 필요**하다고 표시한다
- 기초·기말 재고, 홈오피스, 계좌에서 바로 빠지는 수수료는 이 앱이 다루지 않는다

영수증 사진은 기본적으로 보내지 않는다. 미국 실무에서 CPA는 보통 요약과 내역만 받고,
원본 보관 의무는 납세자에게 있다. 요청이 오면 해당 건만 열어서 내려주면 된다.

## 아직 없는 것

- **재고(inventory) 계산** — Schedule C Part III의 기초·기말 재고는 아직 다루지 않는다.
- **오프라인 입력** — 지금은 저장할 때 인터넷이 필요하다.
- **줄별 사업 사용 비율** — 위에 적은 이유로 일부러 넣지 않았다.

## 참고

세무 신고 자체에 대한 판단은 이 앱이 하지 않는다. 분류가 애매한 지출은 회계사와 확인할 것.
