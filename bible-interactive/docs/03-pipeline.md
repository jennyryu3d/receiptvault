# 에셋 파이프라인 — Git은 레시피, 스토리지는 결과물

상태: 초안 (2026-09-01)

## 한 문장

**저장소에는 결과물을 다시 만들 수 있는 정보만 넣고, 결과물 자체는 오브젝트
스토리지에 두고 해시로 참조한다.**

## 왜

- 4K 스틸과 12분 영상을 git에 넣으면 저장소가 수십 GB가 되고 clone이 불가능해진다
- Git LFS는 GitHub에서 용량·대역폭 과금이 빠르게 오른다
- 새로 합류한 사람이 필요한 것만 받을 수 있어야 한다 (수 MB clone + 필요한 에셋만 pull)
- **AI 생성물은 레시피를 잃으면 두 번 다시 같은 걸 못 만든다**

## 구조

```
git 저장소 (수 MB)              오브젝트 스토리지 (수십 GB)
├─ shots/EP01/*.yaml   ──해시──►  R2 / S3
│   프롬프트·시드·모델              스틸, 클립, 오디오, 최종 영상
│   ·파라미터·승인상태
└─ 이게 유일한 진실
```

## 컷 manifest

컷 하나가 파일 하나. 에셋에 관한 모든 것이 여기 있다. 예시는
`shots/EP01/EP01_C05_S01.yaml`.

지켜야 할 필드:

| 필드 | 왜 필요한가 |
|---|---|
| `seed` | 없으면 재현 불가 |
| `model` + `model_version` | 모델이 업데이트되면 같은 시드로도 결과가 달라진다 |
| `prompt` | 원문 그대로. 요약하지 않는다 |
| `refs` | 캐릭터 일관성의 핵심. 레퍼런스 시트를 고정한다 |
| `sha256` | 스토리지의 파일과 manifest가 어긋났는지 검증 |
| `review.status` | draft → generated → approved. 승인 안 된 건 조립에 들어가지 않는다 |

## 캐릭터 일관성 — 1번 실패 원인

AI 애니메이션이 무너지는 가장 흔한 이유는 컷마다 얼굴이 달라지는 것이다.
대책은 세 가지를 동시에 건다:

1. **레퍼런스 시트 고정** — 인물별 정면/측면/표정 시트를 먼저 확정하고 `assets/char/`에
   버전 박아 커밋한다. 이건 예외적으로 git에 들어간다 (작고, 자주 안 바뀌고, 진실이라서)
2. **시드 규율** — 인물별 베이스 시드를 정하고 컷마다 바꾸지 않는다
3. **사람 눈 검수 게이트** — 생성물은 `review.status: approved` 없이 조립에 못 들어간다

## 제공자 어댑터

이미지·영상 모델은 몇 달마다 바뀐다. 특정 제공자를 코드에 박으면 파이프라인이
그 모델과 함께 늙는다. 인터페이스를 먼저 정하고 제공자는 설정으로 바꾼다.

```
generateStill({ prompt, refs, seed, size })   -> Asset
generateClip({ prompt, firstFrame, seconds, seed }) -> Asset
upscale({ asset, factor })                    -> Asset
```

어댑터는 `pipeline/adapters/<provider>.mjs`. 제공자 선정은 **구현 시점에 실제로
같은 프롬프트를 돌려보고 비교해서** 정한다. 지금 이름을 박아두면 그때 틀린다.

현실적인 한계 하나: 텍스트→영상 모델은 12분 원테이크를 만들지 못한다. 짧은 샷을
생성해 이어붙이는 방식이 된다. 5컷의 원테이크 연출은 **AI 생성이 아니라
언리얼/블렌더 렌더**로 가야 할 가능성이 높다 (= PC가 생긴 뒤).

## 흐름

```
manifest 작성 → 생성(어댑터) → 검수(사람 눈) → 스토리지 업로드
     ↑                                              │
     └──────── 반려 시 프롬프트/시드 수정 ◄───────────┘
                                                    ▼
                                        승인분만 조립 → 웹 빌드 → 배포
```

## 키 관리

키는 클라이언트에 절대 내려가지 않는다. **Cloudflare Worker 프록시**가 키를 시크릿으로
들고 있고, 앱과 파이프라인은 프록시를 호출한다. ConvoTrans에서 이미 쓰는 패턴이다.

- 사람이 늘어도 각자 키를 발급받을 필요가 없다
- 사용량과 비용을 한 곳에서 막을 수 있다
- 유출 시 프록시 시크릿만 교체하면 된다
- **개인 프로젝트에 회사 키를 쓰지 않는다**

Claude API를 쓰는 경우 모델은 `claude-opus-5`를 기본으로 한다.
