# 스택 — 왜 언리얼이 아닌가

상태: 초안 (2026-09-01)

## 결론

| 층 | 선택 | 비고 |
|---|---|---|
| 웹 런타임 | **React + Three.js (필요한 곳만)** | 정적 배포. 지금 바로 만들 수 있다 |
| 시네마틱 | **프리렌더 영상** | AI 생성 → 나중에 언리얼/블렌더 |
| 3D가 정말 필요해지면 | **Godot 4** | 씬 파일이 텍스트라 자동화가 된다 |
| 언리얼 | **렌더 도구로만** | PC 생긴 뒤. 웹 런타임으로는 쓰지 않는다 |

## 근거 1 — 언리얼은 웹으로 나가지 않는다

Epic이 UE4.23 이후 HTML5 익스포트 지원을 중단했고, UE5에는 공식 웹 빌드가 없다.
"웹에서 구동"이 요구사항이면 언리얼은 런타임 후보에서 빠진다. 언리얼로 만든 것을
**영상으로 뽑아** 웹에서 트는 것은 가능하고, 그게 이 프로젝트에서 언리얼의 자리다.

## 근거 2 — 11월까지 PC가 없다

언리얼·유니티·Godot 전부 데스크톱 에디터가 필요하다. 태블릿으로는 불가능하다.
웹 스택은 컨테이너에서 빌드하고 배포할 수 있고, 결과는 브라우저로 확인한다.
**지금 진행 가능한 유일한 선택지다.**

## 근거 3 — 이 작품은 실시간 3D가 필요 없다

5컷은 12분 원테이크 시네마틱이다. 실시간 렌더로 그 품질을 뽑으려면 고사양 GPU를
관객에게 요구하게 되는데, 웹에서는 불가능에 가깝다. 프리렌더하면 품질 상한이 없고
저사양 기기에서도 돌아간다.

인터랙티브 무비 장르의 실제 구조는 대부분 이렇다:

```
영상 트랙 (프리렌더)  ─┐
                       ├─► 동기화 ─► 화면
인터랙션 레이어 (DOM/Canvas) ─┘
```

3컷의 '군중 사이 시점 이동'도 진짜 3D가 아니라 **동기화된 멀티앵글 영상 전환**으로
낼 수 있다. 같은 타임코드를 공유하는 트랙 여러 개를 전환하는 방식이다.
진짜 3D 인터랙션이 필요한 컷이 생기면 그 컷에만 Three.js를 얹는다.

## 엔진 비교

| | 웹 배포 | PC 필요 | 파일이 텍스트인가 | 시네마틱 품질 |
|---|---|---|---|---|
| 언리얼 5 | ✗ 없음 | 필요 | ✗ (블루프린트=바이너리) | 최상 |
| 유니티 | ○ WebGL | 필요 | △ (YAML+바이너리 혼재) | 상 |
| Godot 4 | ○ Web export | 필요 | **✓ .tscn/.gd 전부 텍스트** | 중 |
| 웹 네이티브 | **✓ 정적 호스팅** | **불필요** | **✓ 전부 코드** | 영상 품질에 달림 |

"파일이 텍스트인가"가 중요한 이유: 텍스트면 협업자(사람이든 AI든)가 직접 읽고 고치고
diff를 볼 수 있다. 블루프린트처럼 바이너리면 에디터를 열 수 있는 사람만 손댈 수 있다.

## 다시 볼 조건

아래 중 하나라도 참이 되면 이 결정을 다시 연다:

- 실시간 3D 인터랙션이 감정선에 꼭 필요한 컷이 생겼다 → Godot 4 검토
- 데스크톱/콘솔 출시가 목표에 들어왔다 → 언리얼 검토
- 프리렌더 영상 용량이 웹 배포로 감당 안 된다 → 스트리밍 또는 엔진 전환
